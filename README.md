# 采购标段截标时间核验工具

面向投标专员的网页工具，包含两个相互独立的核验页面：

1. **截标时间核验**：输入公告列表页地址、项目编号、标段号，沿分页抓取原公告、延期公告和终止公告，按发布时间合并出该标段当前有效的投标截止时间。
2. **澄清问题答疑核对**（页面路径 `/qa`）：输入答疑目录地址、项目编号、标段号和多个问题编号，沿同站分页读取答疑详情，核对每个问题是否已答复；答复写“参见另一问题”时跨页追到实际答复，并列出引用经过与来源链接。

应用使用 Python FastAPI，连同本地公告/答疑示例站通过 Docker Compose 启动。示例站为纯本地数据，**构建镜像后整个演示不需要访问互联网**。

## 启动

```bash
docker compose up --build
```

- 核验工具：<http://localhost:8000>
- 本地公告示例站：<http://localhost:8001/notices?page=1>
- OpenAPI：<http://localhost:8000/docs>

首次启动会下载 Python 镜像与依赖；镜像构建完成后，核验、翻页、查看来源链接都在本机完成，可断网演示。

停止：

```bash
docker compose down
```

## 演示用例

首页已提供一键示例：

| 用例 | 项目编号 | 标段 | 预期 |
| --- | --- | --- | --- |
| 投标进行中（已延期） | `DEMO-2026-001` | `02` | 有效截止时间 `2026-11-12 09:30`，来源为第 2 页延期公告 |
| 已终止 | `DEMO-2026-001` | `01` | 状态“已终止”，**不显示有效截止时间**；时间线保留原公告、延期、终止三次变化及各自来源 |
| 不同编号格式 | `DEMO-2026-002` | `A` | 有效截止时间 `2026-11-25 14:00`；A 包的成交结果公告不改变截止时间 |

示例数据故意分布在第 1、2、3 页：`DEMO-2026-001` 的原公告在第 1 页，01 标段延期在第 2 页，终止在第 3 页；同项目 02 标段也有自己的公告，核对 01 标段时不会被混入。

示例站也可以在宿主机通过 <http://localhost:8001/notices?page=1> 直接浏览。工具内预填示例地址 `http://localhost:8001/notices?page=1`；即使应用与示例站分处不同容器，工具也能识别这个公开地址并转到容器内网抓取。核验结果中的所有来源链接会自动转成 `http://localhost:8000/demo/...` 代理链接，因此浏览器也可直接打开。

## 澄清问题答疑核对（`/qa`）

定稿前确认自己提交的澄清问题是否都有答复，以便催问遗漏项。在 <http://localhost:8000/qa> 输入答疑目录 URL、项目编号、标段号和多个问题编号（逗号、顿号、分号、空格或换行分隔），工具沿同站分页读取答疑详情并逐题给出结论。

### 结论口径

| 状态 | 含义 |
| --- | --- |
| 已答复 | 找到实质性答复；若本页只写“参见另一问题 Qxxx”，会跨页追到实际答复，并在“引用经过”中列出每一跳的问题编号与来源链接 |
| 未答复 | 完整读取目录后找不到该问题编号，或找到的答疑记录答复正文为空（含引用链终点答复为空） |
| 待核实 | 出现循环引用、悬空引用（被引用编号不存在），或同一问题编号出现不同的直接答复正文 |
| 无法核定 | 本轮有列表页/详情页抓取或解析失败；漏抓不会被当成未答复，已证实的答复仍然保留 |

其他项目、或同项目其他标段的答疑即使编号相同也不会混入；核对严格限定在输入的项目编号与标段号上。

### 示例数据（项目 `DEMO-2026-001` · 标段 `01`，共 5 页）

| 问题编号 | 演示的情形 | 预期结论 |
| --- | --- | --- |
| `Q001`、`Q009`、`Q010` | 普通直接答复 | 已答复 |
| `Q002` | 答复“参见另一问题 Q003”，Q003 在后面的分页 | 已答复，引用链 Q002 → Q003 |
| `Q011` | 带说明前缀的跨页引用，仍指向 Q003 | 已答复，引用链 Q011 → Q003 |
| `Q004` | Q004 → Q007 → Q008 → Q004 循环引用 | 待核实 |
| `Q005`、`Q006` | 答复正文为空 | 未答复 |
| `Q012` | 同一编号两条不同的直接答复（90 天 / 60 天） | 待核实 |
| `Q201`、`Q301` | 分别属于另一项目、同项目 02 标段 | 核对 01 标段时不计入，按未找到处理 |
| 任意不存在的编号（如 `Q099`） | 目录中没有该编号 | 未答复（抓取完整时） |

### JSON API

```bash
curl -G http://localhost:8000/api/qa-check \
  --data-urlencode 'list_url=http://localhost:8001/qa?page=1' \
  --data-urlencode 'project_no=DEMO-2026-001' \
  --data-urlencode 'section_no=01' \
  --data-urlencode 'question_numbers=Q002' \
  --data-urlencode 'question_numbers=Q004'
```

`question_numbers` 可重复传入；`POST /api/qa-check` 接受 JSON，问题编号放在 `question_numbers` 数组中。返回中每个问题包含 `status`（`answered` / `unanswered` / `needs_review` / `indeterminate`）、实际答复正文、实际答复来源 `answer_source_url`、引用经过 `chain`（每跳带问题编号与来源链接）以及 `reasons`；顶层 `failures` 列出抓取/解析失败的地址与阶段，`round_incomplete` 表示本轮是否存在漏抓。

## 核验规则

1. **分页发现**：从列表页开始，沿 `rel=next`、分页器内的页码/下一页链接继续抓取，直到没有更多页或达到安全上限。
2. **精确匹配标段**：只有详情页中项目编号和目标标段号同时匹配才纳入合并。列表页有明确项目/标段信息时会先排除其他项目和其他标段，详情页仍会再次校验，避免混入同项目其他标段。
3. **按发布时间排序**：将命中的原公告、延期/更正公告、终止公告按详情页发布时间合并。
4. **只应用明确修改**：延期公告只有载明新的投标截止时间时才替换旧时间；页面只是引用旧时间、或只说“另行通知”而没有新时间时，结论为“无法判定”，不会把旧时间继续当作有效时间。
   - 同时支持“原时间……现延期至……”“……变更为……”“变更后：……”等写法，避免把“原时间”误当新时间，也不会把开标时间误当投标截止时间。
5. **终止优先**：一旦终止公告发布，状态固定为“已终止（不再接受投标）”，有效截止时间为空，旧时间只出现在历史时间线中并明确标注失效。
6. **失败即无法判定**：列表页、分页页、候选详情页抓取失败，详情页关键字段无法解析，缺少原公告，或相关公告缺少发布时间导致无法排序时，页面显示“无法判定”和失败/检索地址，并置空有效截止时间。**不会沿用之前的查询结果**。
7. **无缓存**：每次查询都实时重新抓取，不保存、不读取旧结论。

其他公告（如成交结果公告）可以出现在命中的公告列表中，但不会改变标段状态或截止时间。

## JSON API

```bash
curl -G http://localhost:8000/api/check \
  --data-urlencode 'list_url=http://localhost:8001/notices?page=1' \
  --data-urlencode 'project_no=DEMO-2026-001' \
  --data-urlencode 'section_no=01'
```

也支持 `POST /api/check`：

```json
{
  "list_url": "http://localhost:8001/notices?page=1",
  "project_no": "DEMO-2026-001",
  "section_no": "01"
}
```

关键返回字段：

- `status`：`ongoing` / `extended` / `terminated` / `unknown`
- `determinable`：是否有足够证据形成结论
- `effective_deadline`：当前有效截止时间；终止或无法判定时为 `null`
- `deadline_source_url`：当前结论来源链接
- `changes`：按发布时间排列的变化记录，每条都带 `url`
- `failures`：抓取/解析失败地址及原因
- `notices`：命中的目标标段公告（不包含其他标段）

## 本地测试

不启动容器也可运行解析与合并规则测试（需要先安装 `requirements.txt`）：

```bash
python -m unittest discover -s tests -v
```

测试使用 `httpx.MockTransport` / `ASGITransport`，覆盖跨页、延期替换、终止失效、同项目其他标段隔离、详情页失败、缺少原公告和“无新时间的延期”等场景；答疑核对部分覆盖直接答复、空答复、跨页引用、循环引用、悬空引用、同编号答复冲突、其他项目/标段隔离，以及抓取失败时“无法核定而非未答复”的保守口径。

## 边界与限制

- 只抓取 HTTP/HTTPS 的 HTML 页面；链接限定在输入列表页同一站点（scheme + host），不会跟随站外跳转。
- 单次查询设置列表页/详情页数量和响应大小上限，避免误抓大型站点；超过上限时结论为“无法判定”而不是猜测。
- 不处理需要登录、验证码、JavaScript 动态渲染的公告站。
- 日期按页面原始时区文本解析（示例为北京时间），不进行时区换算。
- 示例站数据均为虚构，不代表任何真实采购项目。
